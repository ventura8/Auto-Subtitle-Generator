# Auto-Subtitle-Generator v1.3.2 — Resume & Pivot Sidecar Symlink Hardening

## Release Summary

v1.3.2 closes a medium-severity local vulnerability where resume and
translation pivot logic followed planted `.srt` sidecar symlinks in untrusted
input folders. Previously, planted symlinks (such as `vacation.en.srt` pointing
to a private victim transcript) were parsed as valid transcription text,
skipping speech recognition and translating the victim's subtitles into output
files beside the decoy video. Resume, English pivot reuse, and target language
state checks now refuse symbolic links, bind descriptors, and read SRT cues
safely without following links. There are no CLI, config, or deliverable
filename changes.

## Sidecar Symlink Hardening for Resume and Pivot Passes

1. `_read_resume_srt` in `auto_subtitle.py` checks `is_link(srt_path)` and logs
   a warning when a symlink is encountered, refusing to resume from it. It then
   binds the candidate file via `bind_input` to validate bound bytes rather than
   the pathname.
1. `_load_reusable_pivot_srt_data` and `_classify_target_language_state` in
   `modules/pipeline/translation.py` refuse linked `.srt` sidecars with an
   explicit warning and bind descriptors using `bind_input` before validating
   or parsing cues.
1. `modules/subtitles/srt_io.py` introduces `_open_srt_reader` and
   `_safe_srt_opener` which open SRT files with `O_NOFOLLOW` on POSIX and check
   for symlinks/junctions on Windows, blocking attempts to read through
   symlinks even if called directly.

## Tests

- `tests/orchestration/test_temp_hygiene.py` adds
  `TestResumeAndPivotSymlinkHardening` verifying that planted symlinks to secret
  victim SRT files are rejected during resume, English pivot reuse, target
  language classification, and direct SRT parsing/validation.
- `tests/modules/utils/test_utils_behavior.py` verifies `_safe_srt_opener`
  behavior across symlinks and `/dev/fd/` descriptors.
