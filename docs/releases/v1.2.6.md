# Auto-Subtitle-Generator v1.2.6 — SonarCloud Clean-Up

## Release Summary

v1.2.6 is a maintenance release that clears every finding the v1.2.5
SonarQube Cloud analysis of `main` left open (28 issues: 1 critical,
24 major, 3 minor). There are no changes to CLI flags, configuration keys,
deliverable filenames, or pipeline behaviour.

## Supply-Chain Hardening

### CI installs wheels only (`githubactions:S8541`, 5 findings)

Poetry builds a source distribution by running its setup script on the
runner. `.github/workflows/ci.yml` now sets
`POETRY_INSTALLER_ONLY_BINARY: ":all:"` at workflow level, so every
`poetry install` in every job refuses sdists.

`diffq` (pulled in by `audio-separator` in the `ml` group on non-Windows
platforms) publishes no CPython 3.12 wheel, so the Linux real-ML E2E job names
it — and only it — in `POETRY_INSTALLER_NO_BINARY`. Poetry treats an exact
package name in `no-binary` as overriding `only-binary: :all:`, so every other
package in that job is still wheel-only. Every other package in `poetry.lock`
was checked to ship a wheel for Linux x86_64 and Windows amd64 on CPython
3.12.

### Docker image copies an explicit file list (`docker:S6470`, critical)

`docker/Dockerfile.ubuntu` replaced `COPY . /app` with explicit `COPY`
instructions for the files the installer and E2E suite need
(`pyproject.toml`, `poetry.lock`, `poetry.toml`, `pytest.ini`,
`pyrightconfig.json`, `config.yaml`, `auto_subtitle.py`, the shell scripts,
`modules/`, `tests/`, `typings/`). Anything else in the build context — local
`.env` files, caches, media, coverage output — can no longer reach the image,
independent of `.dockerignore`.

## Tests (`python:S8997`, 17 findings)

Tests that assigned module globals directly now scope the change with
`unittest.mock.patch.object`, which restores the original value even when an
assertion fails:

- `tests/modules/runtime/test_vram_tuning.py` — `TestResolveNllbModelId` uses a

  `tests/modules/configuration/test_config_validation.py`,

## Windows Gate Fix

`modules/runtime/model_cache.py` (added in v1.2.5) looked up `os.geteuid`
with `getattr(os, "geteuid", None)`. On Windows, pylint infers that as
always `None` and failed the local gate with `E1102 not-callable`; CI runs
on Ubuntu, so it never saw this. The lookup now goes through `vars(os)`, and
`tests/modules/test_model_cache.py` shares one `_current_uid()` helper
instead of calling `os.geteuid` directly (`E1101 no-member` on Windows).
Behaviour is unchanged on both platforms.

Three tests in `tests/modules/media/test_input_binding.py` (added in v1.2.4)
still fail on Windows only, identically on the v1.2.5 tree; they pass on
Linux and are tracked separately.
