# Auto-Subtitle-Generator v1.2.8 — Subtitle Mux Input Hardening

## Release Summary

v1.2.8 closes a path through which a party able to write the input folder
could copy another media file the user can read into the `_multilang`
output. It also bumps `urllib3` for three new advisories. There are no
changes to CLI flags, configuration keys, or deliverable filenames.

______________________________________________________________________

## Subtitle Sidecars Are Bound and Validated Before the Mux

The source subtitle (`<base>.<lang>.srt`) was added to the mux after an
existence check only, opened by FFmpeg by name, and mapped with `-map N`
(every stream). Replacing it with a symlink to a video during translation
made FFmpeg stream-copy that video's picture and audio into
`<base>_multilang.<ext>` beside the input.

- `_is_muxable_srt` refuses a sidecar that is a symlink or junction and runs
  `validate_srt` on the source **and** translated SRTs.
- `_bind_mux_inputs` binds every SRT with `bind_input` (`O_NOFOLLOW`,
  regular-file check), like the input video, and validates the bound bytes
  again, so a regular file swapped in after the first check aborts the mux.
- `_build_embed_command` passes each SRT as `-f srt` and maps only its
  subtitle streams (`-map N:s`). A media file posing as an SRT fails the SRT
  demuxer and contributes no video or audio; this was confirmed with real
  FFmpeg against the reported proof of concept.

## Dependencies

- `urllib3` 2.7.0 → 2.8.0 (PYSEC-2026-4175, PYSEC-2026-4176,
  PYSEC-2026-4177). Only that lock entry changes.

## Documentation

- `AGENTS.md` and `docs/pipeline_logic.md` document the mux input rules.
- Version bumped to 1.2.8 in `pyproject.toml` and the
  `modules/configuration/version.py` fallback.

## Breaking Changes

None. A subtitle sidecar that is a link, is not valid SRT, or changes before
the mux is now left out of (or aborts) the mux instead of being muxed.
