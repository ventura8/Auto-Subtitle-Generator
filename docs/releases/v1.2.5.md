# Auto-Subtitle-Generator v1.2.5 — SonarQube Cloud Analysis & Dependency Refresh

## Release Summary

v1.2.5 puts the project under SonarQube Cloud analysis on every pull request,
with the quality gate blocking the build, and fixes the findings that analysis
produced. It also moves `audio-separator` to 0.47 and lifts the `librosa < 1.0`
pin that release made possible.

Of the 91 findings from the first analysis, 63 are fixed — all 5 bugs and 6 of
12 vulnerabilities. 22 were verified as false positives for this codebase and
deliberately left, with the reasoning recorded in the `sonarqube-analysis`
skill so it is not re-litigated. 6 cannot be closed by a code change.

There are no changes to CLI flags, configuration, or deliverable names.

## Analysis Setup

`sonar-project.properties` targets `ventura8_Auto-Subtitle-Generator`. The CI
job runs after `static_analysis` and `technical_validation` and reuses their
coverage artifact rather than re-running the suite, with `fetch-depth: 0` so
new-code detection works, plus a quality-gate step that blocks the build. It is
skipped for pull requests from forks, where the `SONAR_TOKEN` secret is not
exposed.

Two settings live outside the repository and will not be inherited by a fresh
fork: the `SONAR_TOKEN` repository secret, and Automatic Analysis being
disabled on the SonarCloud project. Automatic Analysis cannot ingest a coverage
report — coverage reads 0% — and it conflicts with CI-based analysis.

Scope covers `auto_subtitle.py`, `modules`, the Go launcher, `docker`,
`scripts`, `.github` and the shell installers. The first scan found real GitHub
Actions and Docker findings that a Python-only scope would have dropped.

## Security Fixes

### Path traversal in the translation worker

`run_batch_translation_worker` took its manifest path from `argv`, opened it,
and then opened every `input`, `output` and `en_output` the manifest named,
without checking where any of them pointed.

This took three attempts, and the first two are instructive. Confining the
paths *inside* the manifest left the manifest path itself flowing from `argv`
into `open()`. Validating the manifest path structurally — requiring a
`.manifest.json` inside a `WORK_DIR_SUFFIX` directory — was also correct code,
and Sonar still reported it: taint analysis tracks `argv → open()` and does not
treat validation helpers as sanitizers, so the finding moved rather than
cleared.

The fix removes the sink. The parent writes the manifest to the worker's
**stdin**, an inherited descriptor, and passes only the work directory on the
command line (`--batch-stdin <work_dir>`). The worker never opens a filename it
was handed. `stdin` is used rather than `subprocess` `pass_fds` because
`pass_fds` is POSIX-only and this project ships Windows.

### Separator cache purge

The purge validated a candidate cache directory by pathname and then listed and
unlinked by pathname, so the directory could be swapped between the check and
the use — the guard did not guard the operation it protected. It now opens the
directory once with `O_NOFOLLOW`, validates that descriptor with `fstat`, and
lists and unlinks relative to it, reusing the binding `modules/workdir.py`
already performs. `_open_dir_handle` was promoted to `open_dir_handle` for the
second consumer.

A follow-up review caught a regression in that change: `os.supports_dir_fd` is
empty on Windows, so the descriptor-bound purge returned without deleting
anything on the project's primary target OS, and `SeparatorModel` retried
`load_model` against the same corrupt checkpoint. The rule now matches
`workdir._binding_is_valid`: abort when descriptors are supported but the bind
fails, since that can mean a link or a swapped directory, and fall back to
pathnames only where there is no descriptor support at all.

### Launcher and release workflow

`bash` and `powershell.exe` were resolved through `PATH`; both now resolve to
absolute locations. `softprops/action-gh-release` was pinned to a movable tag
and is now pinned to a commit SHA.

## Dependencies

`audio-separator` 0.44.5 → 0.47.0, `librosa` 0.11 → 1.0, `ruff` → 0.16.8.
Everything else was already at its latest version.

Two `pyproject.toml` changes were required to make `poetry lock` solvable:

1. **Markers carry only `platform_system`.** `requires-python` already pins
   3.12, so `python_version == '3.12' and implementation_name == 'cpython'` on
   every ML entry was redundant — but Poetry still intersected that marker
   space per package across the duplicate `torch`/`torchvision` entries. With
   those clauses present the resolver never terminated; without them it
   completes in about twenty minutes and reports real conflicts.
1. **The exact `nvidia-cublas` pin is removed.** `torch` pulls `cuda-toolkit`,
   and the two `torch` entries resolve to different `cuda-toolkit` versions —
   13.2.1 for the `+cu132` build, 13.0.3 for the plain PyPI build the Darwin
   entry selects — which require different `nvidia-cublas` and
   `nvidia-cuda-nvrtc` versions. Pinning either makes the lock unsolvable for
   the other branch. `nvidia-cudnn-cu13` stays pinned because both builds agree
   on 9.24.0.43.

## Testing

The Go launcher gains tests and CI verification. Previously no Go code was
built in CI at all, so a mistake in the launcher would have reached a release
unnoticed. CI now runs `gofmt`, `go vet` and `go test` over it and
cross-compiles all five release targets, since the interpreter lookup is
per-OS and only Windows exercises `powerShellPath`.

19 `assertRaises` blocks were narrowed to the single call under test. Each
wrapped several calls that could throw, so a failure while building an argument
was indistinguishable from the failure the test meant to assert. An AST sweep
over `tests/` now reports zero such blocks; it also caught one that Sonar had
not yet analysed, so 20 were fixed.

## Hardware Verification

Changes touching the GPU path were exercised on an RTX 3080 Laptop, not only
through the gates. This matters because the CI E2E suite does not exercise
`run_batch_translation_worker` at all, so the worker protocol change had no
real-path coverage from CI.

- A real NLLB batch job translated correctly through the new stdin protocol.
- A manifest with an escaping job output, and a work directory without the
  expected suffix, were both refused before any model load; nothing was written
  outside the work directory.
- `audio-separator` 0.47 separated on the GPU with librosa 1.0 installed, which
  exercises the `get_duration` call the pin existed for.
- `faster-whisper` transcribed on CUDA — the case that matters for dropping the
  cuBLAS pin, since CTranslate2 links it directly.

## Findings Deliberately Not Applied

Three rules misfire on this codebase and were verified against the code rather
than applied:

- **`S7504` (unnecessary `list()`)** — the loops mutate the collection they
  iterate; removing the copy raises `RuntimeError: set changed size during iteration` at runtime.
- **`S8997` (use `monkeypatch`)** — inapplicable to `unittest.TestCase` suites,
  where pytest fixtures are not injected. They already use `addCleanup`.
- **`S125` (commented-out code)** — explanatory comments documenting Windows
  console constants.

Six more cannot be closed by a code change: `githubactions:S8541` (×5) is
inherent to Poetry, which has no flag to forbid sdist builds, and
`docker:S6470` is already constrained by `.dockerignore`, which Sonar cannot
see.

## Known Limitations

Manifest containment is **load-time validation, not a binding**. Job inputs and
outputs are resolved once and opened by name later, so they are not
descriptor-bound the way `modules/safe_io.py` and `modules/workdir.py` bind
theirs. A work directory replaced between validation and use is still a gap,
and `AGENTS.md` records it as such rather than as a guarantee.

`poetry lock` takes roughly twenty minutes on this dependency graph. CI
regenerates the lock whenever `poetry check` reports a mismatch, so that path
is slow when it fires.
