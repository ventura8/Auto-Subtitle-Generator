## 🛰️ SonarQube Cloud analysis in CI

Every pull request raised from a branch in this repository is scanned and
gated. Pull requests from forks are skipped: GitHub does not expose repository
secrets to them, so the scan has no `SONAR_TOKEN` to authenticate with. The job
reuses the `coverage.xml` the test stage already produces rather than
re-running the suite, so the scan adds about a minute. Automatic Analysis is deliberately disabled on the project: it
cannot ingest a coverage report, and it conflicts with CI-based analysis.

The scope covers the Go launcher, the CI workflows, the Dockerfiles and the
shell installers alongside Python — the first scan found real GitHub Actions
and Docker findings that a Python-only scope would have dropped silently.

The zero-suppression policy extends to Sonar: no `# NOSONAR`, and no clearing
a finding as "Won't fix" to pass the gate.

## 🔒 Security fixes from that analysis

- **Path traversal in the translation worker.** The worker took its manifest
  path from `argv` and opened it, then opened every input and output the
  manifest named, without checking where any of them pointed. The manifest now
  arrives on the worker's **stdin** — an inherited descriptor — and only the
  work directory is passed on the command line, so no filename reaches `open()`
  from `argv`. Every path the manifest carries is confined to that work
  directory. The `--batch <manifest path>` mode is gone.
- **Separator cache purge.** Corrupt-checkpoint recovery validated a cache
  directory by pathname and then listed and unlinked by pathname, so the
  directory could be swapped between the check and the use. It now opens the
  directory once with `O_NOFOLLOW`, validates that descriptor, and operates
  relative to it.
- **Launcher interpreter lookup.** `bash` and `powershell.exe` were resolved
  through `PATH`, which a writable entry could hijack. Both now resolve to
  absolute locations.
- **Unpinned release action.** `softprops/action-gh-release` was pinned to a
  movable tag; it is now pinned to a commit SHA.

## 📦 Dependencies

`audio-separator` 0.44.5 → 0.47.0 and `librosa` 0.11 → 1.0. The `librosa < 1.0`
pin existed because `audio-separator` called `get_duration(filename=...)`,
removed in librosa 1.0; 0.47.0 uses the supported form.

Making the lock solvable again needed two changes to `pyproject.toml`.
Dependency markers now carry only `platform_system` — `requires-python` already
pins 3.12, and repeating `python_version` / `implementation_name` on every ML
entry left Poetry intersecting a marker space large enough that `poetry lock`
never finished. The exact `nvidia-cublas` pin is also removed: `torch` pulls
`cuda-toolkit`, the two `torch` entries resolve to different `cuda-toolkit`
versions, and those require different `nvidia-*` versions, so pinning for one
branch made the lock unsolvable for the other.

## 🧪 Testing and verification

The Go launcher now has tests, and CI runs `gofmt`, `go vet` and `go test` over
it and cross-compiles all five release targets — previously none of that code
was built in CI at all.

`assertRaises` blocks across the suite were narrowed to the single call under
test. Each previously wrapped several calls, so a failure while building an
argument was indistinguishable from the failure the test meant to assert.

Changes touching the GPU path were verified on real hardware, not only by the
gates: a real NLLB batch job through the new stdin protocol, `audio-separator`
0.47 separating with librosa 1.0 installed, and `faster-whisper` transcribing
on CUDA — the case that matters for dropping the cuBLAS pin, since CTranslate2
links it directly.

## ⚠️ Known limitations

Manifest containment is **load-time validation, not a binding**: job inputs and
outputs are resolved once and opened by name later, so they are not
descriptor-bound the way `modules/safe_io.py` and `modules/workdir.py` bind
theirs. A work directory replaced between validation and use remains a gap.

On Windows the separator-checkpoint purge falls back to pathnames, because
Python exposes no descriptor-relative unlink there. It checks ownership and
re-checks each entry as a real file before unlinking, but cannot rule out a
directory swapped between that check and the unlink.

`poetry lock` takes roughly twenty minutes on this dependency graph. It
terminates correctly, but CI regenerates the lock whenever `poetry check`
reports a mismatch, so that path is slow when it fires.
