# Auto-Subtitle-Generator v1.3.3 — Private Audio Stage, Held Worker Directory & Locked Bootstrap

## Release Summary

v1.3.3 closes five findings from the 2026-10-30 security review. All of them
come from one fact: the per-video work directory (`<base>.asg-temp/`) lives in
the untrusted input folder, and its owner can list it and keep writing into it
while a model loads for minutes. Before this release, Audio-Separator wrote its
predictable stem name into a listable scratch directory there (planted link →
arbitrary file overwrite), work-directory audio was reopened by pathname after
model loads (swapped link → another recording transcribed into the decoy's
subtitles), and the translation worker staged JSON with `mkstemp` → close →
reopen and opened manifest paths by name long after validating them. The
installers also installed whatever Poetry PyPI served. All dependencies are
updated as well. There are no CLI, config or deliverable filename changes.

______________________________________________________________________

## 1. Private audio stage (MEDIUM ×2: separator overwrite, work-dir audio reopened)

- New `modules/media/audio_stage.py`. `transcribe_video_audio` opens an
  `AudioStage`: a `tempfile.mkdtemp()` directory (`0700`) under
  `%TEMP%`/`$TMPDIR`, outside the input tree, removed when transcription ends.
- Work-directory audio enters the stage through `import_file` **before any
  model loads**: the file is opened with `input_binding.open_bound_input`
  (no link followed below the selected input folder, regular file required)
  and its bytes copied from that descriptor. A failed copy removes only the
  partial file it created.
- Audio-Separator reads the staged `*_temp.wav` and writes into a stage
  sub-directory, so its by-pathname stem write can no longer be redirected.
  Chunk inputs, raw and trimmed chunk stems and the joined vocal track are
  made in the stage; the join reads staged stems only.
- The work directory receives finished files through the new
  `safe_io.copy_file_into` (`atomic_binary_writer`) for resume only. A link
  planted at a resume name is refused with a WARNING and costs only the
  resume; transcription continues with the staged vocals.
- Whisper, the language vote and Canary/Parakeet read the staged copy. The
  `<base>_asr16k.wav` transcode (possibly several GB) stays in the work
  directory and is opened once through `open_bound_input`; `soundfile` reads
  that held descriptor for the whole decode.
- Cost: one extra copy of the transcription audio in the temp directory
  (16 kHz mono float, about 230 MB per hour) plus the vocal stem.

## 2. Held work directory in the translation worker (MEDIUM ×2: mkstemp reopen, load-time-only containment)

- New `modules/held_dir.py` (`HeldDirectory`). `_load_contained_manifest`
  now requires each manifest path to name an entry *directly* inside the work
  directory and holds that directory before the model loads.
- POSIX: every job read, existence check, write and unlink goes through the
  held `O_NOFOLLOW` directory descriptor (`dir_fd`); entries are opened with
  `O_NOFOLLOW | O_NONBLOCK` and must be regular files. A link planted at a job
  file, or the whole work directory replaced by a link, is no longer followed.
- Windows: the directory identity and a link/junction check are re-verified
  before every operation, and reads compare the opened file's identity with
  its `lstat`.
- Worker JSON is written through the descriptor of an exclusively created
  `.asg-tmp-<hex>.tmp` entry and renamed only while that entry is still the
  one created; `tempfile.mkstemp` / close / reopen is gone. The legacy
  single-file mode writes through `safe_io.atomic_text_writer`.
- The parent reads worker outputs and the manifest it pipes to the worker
  through `translation._read_work_file` (`open_bound_input`), refusing links.

## 3. Hash-locked pip and Poetry (MEDIUM: unpinned Poetry in installers)

- New `bootstrap-requirements.txt`: pip 26.2.2 and Poetry 2.4.3 (the version
  CI already used) plus every dependency Poetry pulls in, for all platforms,
  generated by `uv pip compile --universal --generate-hashes` (command in its
  header). Poetry is deliberately not bumped: 2.5.1 never finishes resolving
  this project's lock, while 2.4.3 resolves it in seconds.
- `install_dependencies.sh`, `install_dependencies.ps1` and every CI job
  install it with `pip install --require-hashes --only-binary=:all: -r ...`;
  the CI `POETRY_VERSION` pin is replaced by the file. The release bundles and
  the Ubuntu Docker image ship it.

## 4. Robustness

- `input_binding.open_bound_input` and `HeldDirectory` open with
  `O_NONBLOCK`, so a FIFO planted at a bound name is refused by the
  regular-file check instead of hanging the run.

## 5. Dependency updates

- torch `2.14.0+cu132` → `2.15.0+cu132` (Darwin `>=2.15,<2.16`), torchvision
  `0.29.0+cu132` → `0.29.1+cu132`, nvidia-cudnn-cu13 `9.24.0.43` →
  `9.26.0.51` (the version both torch 2.15 builds require).
- transformers `^5.22.1`, audio-separator `^0.48.0`.
- Dev: pytest `^9.2.0`, pylint `^4.1.3`, flake8 `^7.5.0`, black `^26.10.1`,
  isort `^9.0.2`, ruff `^0.17.3`, mypy `^2.4.1`, types-pyyaml, pymarkdownlnt.
- `poetry.lock` refreshed for every transitive dependency (`poetry update`).
- PyAV is capped at `>=18.1,<19` in the `ml` group: faster-whisper 1.2.1 (the
  latest) still passes `metadata_errors=` to `av.open`, which PyAV 19 removed,
  so every transcription failed with a `TypeError` in the end-to-end run.

## Breaking Changes

None. Manifest paths must now sit directly in the work directory, which is
where the parent has always placed them.
