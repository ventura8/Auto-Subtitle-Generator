# Auto-Subtitle-Generator v1.2.3 — Per-Video Work Directory & Temp Hygiene

## Release Summary

v1.2.3 is a reliability and file-hygiene release. Every temporary artifact the
pipeline produces for an input video now lives in a single per-video work
directory, `<video name>.asg-temp/`, instead of being scattered beside the
video. That one change fixes three long-standing problems at once: the input
folder is no longer littered with intermediates, an interrupted run can now be
resumed from the last completed stage after a crash or power outage, and a
finished video leaves nothing behind.

The previous behaviour deleted the expensive intermediates (extracted audio,
isolated vocals) on *every* exit — including a crash or `Ctrl+C` — while the
cheap-to-recreate source-language sidecar was never cleaned up at all. Both
are now inverted to the correct policy: **keep everything on an unclean exit,
remove everything on a clean one.**

There are no changes to CLI flags, configuration, or the names of any
deliverable. Only the per-language `.srt` files and the `_multilang` container
are written next to the input video.

## The Problem

Temporary files were written directly into the (untrusted) input directory
using the video's base name:

| Artifact | Old location | Stage |
| --- | --- | --- |
| Extracted audio | `movie_temp.wav` | Audio prep |
| Isolated vocals | `movie_temp_(Vocals)_*.wav` | Vocal separation |
| Worker input | `movie.common_input.json` | Translation |
| Job manifest | `movie.manifest.json` | Translation |
| English pivot | `movie.pivot_pivoted.json` | Translation |
| Per-language output | `.temp_output.movie.<lang>.json` | Translation |
| Resume sidecar | `movie.source_lang.txt` | Transcription |
| Scratch entries | `.asg-tmp-*/` | All atomic writes |

Four concrete defects followed from that layout:

1. **Bleed on success.** `movie.source_lang.txt` was never matched by
   `cleanup_temp_files`, so it survived every completed video.
1. **Resume data destroyed on failure.** `process_video` called
   `cleanup_temp_files` from a `finally` block, so a failed, crashed, or
   `Ctrl+C`-interrupted run deleted the extracted WAV and the isolated vocals —
   the two most expensive intermediates — forcing a full redo.
1. **Scratch leak on interrupt.** `embed_subtitles` discarded its mux scratch
   file only in an `except (OSError, RuntimeError, ValueError)` handler.
   `KeyboardInterrupt` derives from `BaseException`, so `Ctrl+C` during muxing
   left a multi-hundred-megabyte scratch directory behind.
1. **Unvalidated resume.** A vocal stem truncated by a power cut, or a pivot
   file left over from a previous transcription, was reused as-is.

## `modules/workdir.py` (new)

A stdlib-only module that owns the per-video work directory.

```text
E:\Videos\
├── movie.mp4                     # input
├── movie.ro.srt                  # deliverable
├── movie.en.srt                  # deliverable
├── movie_multilang.mp4           # deliverable
└── movie.asg-temp/               # everything temporary
    ├── movie_temp.wav
    ├── movie_temp_(Vocals)_model_bs_roformer_....wav
    ├── movie.common_input.json
    ├── movie.manifest.json
    ├── movie.pivot_pivoted.json
    ├── movie.source_lang.txt
    └── .asg-tmp-<tag>-<rand>/    # in-flight atomic writes
```

### Public API

- `work_dir_path(folder, base_name)` — pure path computation, no I/O.
- `work_dir_exists(folder, base_name)` — true only for a real, non-linked
  directory.
- `ensure_work_dir(folder, base_name)` — creates the directory `0700` on first
  use and reuses it afterwards (this is what makes resume work). A symlink,
  junction, or regular file occupying the name raises `SymlinkRefusedError`,
  so temp writes can never be redirected out of the folder. A lost creation
  race is absorbed and re-validated rather than raised.
- `purge_work_dir(folder, base_name)` — removes the directory and everything
  the pipeline put in it; returns `False` and logs when something is left.
- `remove_scratch_dir(scratch_dir)` — empties and removes one `.asg-tmp-*`
  directory, used by the vocal-separation stage.

### Deliberately shallow removal

The work directory is created by this pipeline, but it sits in an untrusted
input folder, so cleanup **never recurses** — consistent with the `safe_io`
rule introduced in v1.2.2:

- Regular files and symlinks directly inside the work directory are unlinked.
  A symlink is removed *as a link*; its target is never followed or touched.
- `.asg-tmp-*` sub-directories are emptied one level down (files only) and
  `rmdir`-ed.
- Anything else — an unexpected sub-directory, or a planted `.asg-tmp-*`
  directory that itself contains a directory — is left in place, counted, and
  reported in a warning. `purge_work_dir` then returns `False`.
- Unlink and `rmdir` retry three times with a short sleep to ride out
  transient Windows file locks from a just-exited FFmpeg or worker process.

## Stage-by-Stage Changes

### Audio preparation — `modules/media/ffmpeg_utils.py`

`extract_clean_audio` now calls `ensure_work_dir` and writes
`<base>_temp.wav` inside it, reserving its FFmpeg scratch file there as well.
The resume check (`_has_valid_temp_audio`) is unchanged and simply looks in
the new location.

### Vocal separation — `modules/pipeline/transcription.py`

Audio-Separator writes stems under predictable names, so it is no longer
pointed at the input directory. `_run_vocal_separation` creates a private
`.asg-tmp-*` directory inside the work directory via the new
`safe_io.create_private_dir`, passes that as the separator's `output_dir`, and
moves only the finished vocal stem out into the work directory. The scratch
directory is removed in a `finally`, so a crash mid-separation cannot leave a
half-written file under the name that resume looks for. The destination move
goes through `reject_symlink`, and the non-vocal stems are discarded with the
scratch directory.

`_get_separated_vocal_path` now scans the work directory and **validates**
each candidate: the stem must be a regular file whose probed duration matches
`<base>_temp.wav` within 2 seconds. A truncated leftover is logged and deleted
rather than resumed.

### Transcription resume sidecar — `auto_subtitle.py`

`<base>.source_lang.txt` moved into the work directory, which is created
on demand before the write.

### Translation — `modules/pipeline/translation.py`

`common_input.json`, `manifest.json`, `pivot_pivoted.json`, and every
`.temp_output.<lang>.json` now resolve inside the work directory via the new
`_temp_output_path` helper, and the translated-SRT write reserves its scratch
there too. The manifest handed to the isolated worker therefore carries
work-directory paths, so the child process inherits the layout without needing
to know about it.

Worker temp-file cleanup is now conditional. `_run_worker_process` tracks
completion and calls the new `_finish_worker_temp_files`: on success the temp
files are removed as before; on failure or interrupt they are kept and a
warning names the directory holding them. This is what preserves the English
pivot — the single most expensive artifact for a non-English source — across a
failed run.

### Isolated worker — `modules/pipeline/isolated_translator.py`

Because the pivot file now survives failures, reusing it has to be safe.
`_reuse_existing_pivot_output_if_available` no longer trusts the file's
existence: `_load_pivot_output_matching_input` loads both the stored pivot and
the current worker input and requires equal length and identical `start`/`end`
timings on every cue. A stale or corrupt pivot is logged, discarded, and the
pivot pass reruns.

### Muxing — `auto_subtitle.py`

`embed_subtitles` was split so the reservation happens first (its failure
still yields the established logged `None`), and the mux itself runs in
`_mux_and_promote`, which discards the scratch file in a `finally` when it was
not promoted. `Ctrl+C` during muxing is now clean.

### End-of-video policy — `auto_subtitle.py`

`process_video` no longer cleans up unconditionally. The new
`_finish_temp_hygiene` classifies the outcome with the existing
`utils.classify_batch_result`:

| Outcome | Action |
| --- | --- |
| Muxed successfully | purge work directory + legacy sweep |
| No speech detected | purge work directory + legacy sweep |
| `_multilang` output already exists | purge work directory + legacy sweep |
| Failure, exception, `Ctrl+C`, power loss | **keep** everything, log the path |

### VRAM-aware model selection and batch sizing — `modules/runtime/vram_tuning.py` (new)

Validating this release on an RTX 3080 Laptop (8 GB) exposed the failure the
old static configuration hides: `models.nllb` pinned NLLB-200-3.3B, whose
6.3 GB of fp16 weights do not fit, so loading hit 130 CUDA out-of-memory
retries and the loader's CPU fallback then ran the whole model on the laptop
CPU at 850 % CPU, 160 MiB on the GPU and 0.4x realtime, without logging a
word. Three changes make the pipeline tune itself to the card:

- **Model selection.** `models.nllb` now defaults to `auto`, which picks the
  largest NLLB whose fp16 weights fit 60 % of the usable VRAM: the 3.3B from
  11 GB, the distilled 1.3B from 5 GB, the distilled 600M below. An explicit
  id is honoured, with a warning when it will not fit, and the CPU fallback
  now logs a warning naming the fix.
- **Dynamic batch.** After the translation worker loads the model it reads
  the VRAM still free and sizes `nllb_batch` from measured per-item
  activation cost scaled by `num_beams`, using 80 % of that free memory and
  never exceeding the profile cap (now 16 everywhere memory allows, 8 on
  `LOW`). Because it reads *free* memory, a GPU shared with another process
  gets a smaller batch automatically. `performance.nllb_batch` still pins it.
- **`max_vram_usage_gb` moves the whole tier.** Capping a 32 GB card at 4 GB
  now yields the `LOW` profile, the 600M model, int8 Whisper and a batch
  sized inside the cap rather than off the card's real free memory, and the
  startup banner reads `config.yaml` first so it shows the capped tier.
  Validated on the RTX 5090 with the cap: 37 tracks, zero fallbacks.
- **Whisper precision and a `LOW` tier.** Faster-Whisper uses
  `int8_float16` below 6 GB, and profiles are now `ULTRA` (>= 24 GB),
  `HIGH` (>= 12), `MID` (>= 6), `LOW`, `CPU_ONLY`. The previously unused
  `performance.max_vram_usage_gb` is honoured as a cap on the VRAM planned
  against.

The worker also batches cues in order of text length and restores cue
order afterwards. A batch is padded to its longest cue and beam-searched
until that cue finishes, so on real subtitles a batch of 32 measured no
faster than 8; grouping similar lengths is what lets larger batches pay
off. Progress is now reported by cue count.

Validated end to end on the same RTX 3080 Laptop, with two other GPU jobs
sharing the card: `auto` chose the distilled 1.3B and loaded it on the GPU
(2.56 GB resident), the worker saw 1.3 GB free and sized the batch to 10,
the GPU was busy in 120 of 122 samples with zero CPU-fallback warnings, and
all 36 languages translated in 3:42 (6 s per language) where the old build
was taking over 7 minutes per language on the CPU. The 2:13 test video
finished in 5:35 with 37 subtitle tracks, the muxed output, and nothing left
in the work directory.

All constants are calibrated on the RTX 5090 with the production generate
settings (fp16 weights 6.27 / 2.59 / 1.15 GB; activations 0.154 / 0.093 /
0.063 GB per item at 10 beams for 3.3B / 1.3B / 600M) and documented in
`docs/hardware_optimization.md`.

### Chunked vocal separation for long inputs — `modules/pipeline/transcription.py`

Audio-Separator loads the entire input into RAM at 44.1 kHz stereo float32
and writes a stem of the same shape (measured 344 KB/s). For a 4-hour
recording that is a 5 GB array before the model starts, several times that
at peak, and a 5 GB output stem past the 4 GB RIFF WAV limit. The model
bounds VRAM by segmenting internally, so this was purely a host-RAM and
file-format failure waiting to happen on long inputs.

Inputs longer than the new `separation_chunk_minutes` setting (default 30;
`0` disables) are now separated window by window. Each window is cut with
2 s of context on both sides into the private scratch directory, separated
there, trimmed back to the exact window and downmixed to the 16 kHz mono
Whisper consumes, and landed atomically as `<base>_sepchunk_NNN.wav` in the
work directory. The stems are then joined with the FFmpeg concat demuxer
into `<base>_temp_(Vocals)_chunked.wav` and the chunk files removed. A
finished chunk stem of the right duration is reused on resume, so a power
loss during a multi-hour separation costs at most one chunk. A tail shorter
than 60 s folds into the previous window rather than becoming a tiny chunk.

Peak RAM per 30-minute chunk is around 3 GB and every intermediate stays
under 1 GB, so multi-hour videos now work on a 16 GB laptop. The joined
16 kHz mono stem is also 5.5× smaller than the old 44.1 kHz stereo one.

Validated on the RTX 5090 with the 2:13 interview at a 1-minute chunk
size: the cue spanning the 60 s seam was identical to the unchunked
baseline with timestamps within 20 ms, the remaining differences were
ordinary Whisper variance (two places read *more* correctly), and a run
force-killed during chunk 2 resumed from chunk 1's stem, finished, and
purged everything including the stale scratch directory.

Extraction now passes `-rf64 auto` so a source WAV past 17 h (the RIFF
limit at 16 kHz mono float) stays valid. Transcription, translation and
muxing needed no change: `faster-whisper` decodes to 16 kHz mono (0.9 GB
for 4 h) and windows internally, the worker holds only segment text, and
the mux is a stream copy.

### Toolchain fixes surfaced by cross-platform validation

- **`.gitattributes` pins LF.** A Windows clone with `core.autocrlf=true` got
  CRLF working copies while every blob was LF. That caused two real failures
  this cycle: Taplo rejected `pyproject.toml`, so `run_local_pipeline.ps1`
  halted before running a single test, and `git archive` exported CRLF shell
  scripts that Linux bash refused. Every text file now checks out as LF on
  every platform (`*.bat` keeps CRLF for `cmd.exe`); no blob changed. The
  Windows gate now runs to completion.
- **pip-audit audits the lock for this platform.** The PowerShell gate parsed
  `poetry.lock` with first-entry-wins, which picked the `implementation_name != "cpython"` torch entry (2.10.0) and reported CVEs for a version the
  project never installs, while CI audited its venv, which is installed
  without the `ml` group and so never contained torch at all. The new
  `tests/tools/lock_requirements.py` evaluates each entry's environment
  markers (string or per-group table) and keeps the highest applicable
  version; both gates and CI now audit the same platform-correct set.

### Review follow-ups (PR #11)

CodeRabbit's review of the pull request produced nine findings; all were
verified against the code and fixed:

- **Resume state is bound to the input** (`workdir.bind_work_dir_to_source`).
  The work directory was keyed only by folder and base name, so a video
  replaced by another file of the same name — and the same duration, which
  the existing checks could not tell apart — would have been transcribed
  from the previous file's extracted audio. `process_video` now stamps the
  directory with the input's size and mtime (`source.json`) and discards it
  when the stamp is missing or differs; if the stale directory cannot be
  removed the video fails instead of reusing it. Validating this on real
  media showed the same hazard one layer up: the SRT files the failed run
  had already written beside the video were resumed from, so the replaced
  input received the old file's subtitles. When the input changed, that run
  now also ignores the SRT files beside the video (no source resume, every
  target redone, no English pivot reuse) and regenerates them; nothing
  beside the video is ever deleted.
- **Chunk join with relative input paths.** The concat manifest wrote paths
  as given; FFmpeg resolves relative manifest entries against the manifest's
  directory, so `python auto_subtitle.py clip.mp4` on a multi-hour input
  would have failed at the join. Entries are now absolute.
- **A pinned `nllb_batch` survives hardware detection.** The worker loads
  config (which applies the pin) and only then calls `detect_hardware`, whose
  profile tuning replaced the pinned value with the profile cap.
- **Fractional `max_vram_usage_gb` is preserved** (`0.5` was truncated to
  "no cap").
- **Pivot reuse validates shapes**: a scalar or object where a list of cues
  was expected, or a non-string `text`, now discards the pivot instead of
  raising inside the worker.
- **`lock_requirements` treats Poetry's `<empty>` marker as never
  applicable**, so the audit no longer reports a `nvidia-cusparse` version
  that is never installed in place of the one that is.
- **Test hygiene guard only removes what the test created**; a resumable
  work directory already present in the repository root is left alone.
- Docs: the `config.yaml` note now says the CPU fallback is logged; the
  `unittest.main()` guard in `test_vram_tuning.py` moved to the end of the
  file so direct execution runs every class.

### `--cpu` actually runs on the CPU — `modules/runtime/bootstrap.py`

Validating the CPU-only path on a machine with a GPU showed that `--cpu`
was not honoured at all: it set `CUDA_VISIBLE_DEVICES=""`, and the current
torch 2.14/cu132 build still reported the card as available and used it
for the separator, Whisper and NLLB. The flag now sets `-1`, the value CUDA
documents for hiding every device, through one helper
(`force_cpu_only_env`) that both the pre-import bootstrap and the argument
parser use. Every CUDA probe goes through the new
`optional_imports.is_cuda_usable()`, which also requires
`torch.cuda.device_count() > 0`, and `is_cuda_explicitly_disabled()`
recognises negative id lists so the bundled cuBLAS directory (whose
`libnvblas.so` hijacks CPU BLAS) is not injected on a CPU run.

The same run exposed that a redirected stdout on Windows crashed with
`UnicodeEncodeError` (`charmap`) on the first Romanian transcript line, since
the console defaults to the ANSI code page when it is not a terminal.
`init_console()` now reconfigures stdout and stderr to UTF-8 with
replacement, so logging to a file or a service wrapper keeps running.

### Legacy sweep — `modules/utils.py`

`cleanup_temp_files` is now documented as a compatibility sweep for sidecars
written beside the video by releases up to v1.2.2, and it finally matches
`<base>.source_lang.txt`. Upgrading users get their old stray files cleaned up
on the next completed video. It still never recurses and still ignores
`.asg-tmp-*`.

## `modules/safe_io.py` Extensions

Backwards-compatible additions; every existing call site behaves identically.

- `reserve_temp_path(final_path, scratch_dir=None)` and
  `atomic_text_writer(path, encoding="utf-8", scratch_dir=None)` accept an
  optional `scratch_dir`. When given, the private scratch directory is created
  there instead of beside the destination, so an SRT or `_multilang` file
  destined for the input folder still stages inside the work directory. The
  promotion is a cross-directory `os.replace` within the same filesystem.
- `create_private_dir(directory, tag)` is a new public wrapper over the
  existing private helper, used to hand Audio-Separator an unpredictable,
  `0700`, pipeline-owned output directory.
- `modules/media/ffmpeg_utils.py` gains `run_ffmpeg_quiet`,
  `write_audio_window` and `concat_audio_files` for the chunk cut, trim and
  join steps; all three write only to private scratch paths and enable RF64.
- The `_reserve` parent-directory choice was extracted into `_scratch_parent`
  to keep every function at radon grade A.

## Verification

Beyond the unit suite, the release was exercised against real media
(a 2-minute Romanian interview, 36 target languages, vocal separation on):

1. **Clean run** — video processed end to end; work directory created, used
   by every stage, and removed on completion. Only the 37 SRT files and the
   `_multilang` container remained beside the video.
1. **Simulated power loss** — the process tree was force-killed
   (`taskkill /F /T`) mid-translation after four languages had been written.
   The work directory survived intact with the extracted WAV, isolated
   vocals, manifest, worker input, and English pivot. Nothing else was left
   in the folder.
1. **Resume** — re-running the same file skipped transcription (valid source
   SRT), reused the existing English pivot, reported
   `36 Total | 32 To Do | 4 Skipped`, translated only the remainder, muxed,
   and purged the work directory. The input folder ended clean.
1. **CPU-only run** — `--cpu` on the RTX 5090 box with stdout redirected to a
   file: banner reported `CPU (0 GB VRAM)` / `CPU_ONLY`, the separator and
   Whisper ran on the CPU with no cuBLAS load attempt, 37 SRT files and the
   `_multilang` container were produced, the diacritics survived the
   redirect, and no work directory was left (12 min for a 20 s clip, as
   expected on the CPU).
1. **Relative input path with chunking** — `python auto_subtitle.py clip.mp4`
   from the video's folder on the 2:13 interview with
   `separation_chunk_minutes: 1`: two chunk stems joined through the concat
   manifest, 37 SRT files, work directory removed.
1. **Replaced input** — a run on the 20 s clip was force-killed
   mid-translation (14 SRT files and the work directory left), the file was
   swapped for the 2:13 interview under the same name, and the re-run logged
   both `[Resume]` warnings, re-extracted and re-transcribed (26 cues),
   translated all 36 languages with 0 skipped, and left nothing behind.
1. **Linux guest** — a clean Ubuntu 26.04 container (uv-provisioned Python
   3.12, ffmpeg) cloned the repository, ran `install_dependencies.sh ml,dev`,
   and passed the full `run_local_pipeline.sh` gate; the `.gitattributes`
   checkout was LF-clean and the `dir_fd` binding was active. The same guest
   then ran the `--cpu` pipeline on the clip to completion (auto-selected
   `nllb-200-distilled-600M`, 37 SRT files, `_multilang` container, work
   directory removed, exit 0).

## Upgrade Notes

- Temp files from a v1.2.2-or-earlier interrupted run remain beside the video.
  They are swept automatically the next time that video completes, or can be
  deleted by hand.
- Work directories left by an interrupted v1.2.3 run are intentional — they
  are the resume state. Deleting one only costs the re-extraction and
  re-translation of that video.
- Automation that globbed the input folder for `*_temp.wav` or
  `*.manifest.json` should look inside `<base>.asg-temp/` instead.

## Quality Gates

Run `./run_local_pipeline.sh` (or `.\run_local_pipeline.ps1`) to reproduce the

## Breaking Changes

- **Temporary artifacts moved out of the input folder.** Every intermediate now
  lives in `<base>.asg-temp/` instead of directly beside the video.
  Integrations that glob the input folder for `*_temp.wav`,
  `*.manifest.json`, `*.common_input.json`, `*.pivot_pivoted.json`,
  `.temp_output.*.json` or `*.source_lang.txt` will no longer find them and
  must look inside `<base>.asg-temp/`. These paths were documented in the
  v1.2.2 release notes, so this is a visible contract change rather than an
  internal detail.
- **An unfinished run now leaves a directory behind on purpose.** Earlier
  releases cleaned up on every exit, so the input folder was always bare
  afterwards. A failed, crashed or interrupted v1.2.3 run intentionally keeps
  `<base>.asg-temp/` as its resume state. Tooling that asserts the input
  folder contains nothing but the video and its deliverables needs updating.
- **`models.nllb` defaults to `auto`.** A card under 11 GB now translates
  with the distilled 1.3B instead of the 3.3B it could not actually run on
  the GPU. Set `models.nllb: "facebook/nllb-200-3.3B"` explicitly to keep
  the old choice; a warning is logged when it will not fit.
- Deliverable names are unchanged: the per-language `.srt` files and the
  `_multilang` container are still written next to the video, and CLI flags
  are untouched. See the Upgrade Notes above for the migration steps.
