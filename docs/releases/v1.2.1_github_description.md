# Auto-Subtitle-Generator v1.2.1 — Dependency & Toolchain Refresh

A maintenance release. Every production, ML, developer, and CI/CD dependency was
audited against its upstream registry and moved to the latest final version the
resolver accepts. No behaviour changes, no API changes.

## 🎯 CUDA 13.3.1 — not available from PyTorch

NVIDIA shipped CUDA 13.3.1, but **PyTorch skipped the version entirely.**
Probing the wheel indexes:

| Variant | stable | nightly |
| ------- | ------ | ------- |
| `cu132` | 200 | 200 |
| `cu133` | 403 | 403 |
| `cu134` | 403 | 200 |

There is no `cu133` artifact to upgrade to on either channel — pinning it would
break every GPU install. PyTorch's next CUDA target is **13.4**, currently
nightly-only.

Additionally, `torch 2.13.0+cu132` hard-pins the CUDA 13.2.1 component stack
(`nvidia-cublas ==13.4.0.1.*`, `nvidia-cudnn-cu13 9.20.0.48`); raising either
fails version solving. The latest final `torch` remains `2.13.0` — `2.14.0`
wheels exist on the CUDA index but not on PyPI, so they are pre-final.

Revisit when `cu134` reaches the stable channel.

## ⏸️ audio-separator 0.47.0 — deferred

Prepared, then reverted: 0.47.0 makes Poetry's resolver blow up
combinatorially, with locks running 8–150+ minutes against a config that
otherwise locks in ~11 seconds. Bisected to 0.47.0 alone (not `librosa`); the
cause is a `Duplicate dependencies for nvidia-cublas` conflict introduced by
its new darwin/arm64 `torch>=2.13` marker pulling in PyPI `torch`, which
depends on `cuda-toolkit 13.0.3` rather than the cu132 wheel's `13.2.1`.
`audio-separator` stays at `^0.44.5` and `librosa` keeps its `<1.0` ceiling.
