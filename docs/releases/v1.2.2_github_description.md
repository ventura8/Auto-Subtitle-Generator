# Auto-Subtitle-Generator v1.2.2 — Symlink-Safe Sidecar Writes + Dependency Refresh

A security hardening and maintenance release. No intended changes to
normal-path behaviour, CLI, or configuration, and output filenames are
unchanged; symlinked outputs and symlinked resume audio are now rejected.

______________________________________________________________________

## 🔒 Security fix — symlink following in the input directory (MEDIUM)

The pipeline writes sidecars next to the input video with `open(..., "w")` and
FFmpeg `-y`, both of which follow symbolic links. A folder containing a video
plus planted symlinks named `movie.common_input.json`, `movie.manifest.json`,
`movie.en.srt.tmp`, `movie_temp.wav`, or `movie_multilang.mp4` could redirect
those writes at any file the user can write — `~/.ssh/authorized_keys`, shell
rc files, application configs.

**Fixed.** All sidecar writes now go through the new `modules/safe_io.py`:

- Every write is a `ScratchReservation`: private `0700` directory, exclusive
  `O_EXCL | O_NOFOLLOW` file (umask applied at creation, never modified),
  recorded device/inode identities.
- Text goes through the creation descriptor; FFmpeg `-y` only ever targets
  the reserved scratch file.
- Promotion re-verifies identities and, on POSIX, renames through the held
  directory descriptor (`renameat`) so a renamed scratch directory cannot
  redirect it; symlink destinations and replaced scratch entries are refused
  (`SymlinkRefusedError`).
- Discard is bound the same way and only ever `rmdir`s — no recursion, so
  planted directories/junctions are never walked; the per-video cleanup scan
  no longer touches `.asg-tmp-*` at all.
- Scratch names use `.asg-tmp-<stem[:24]>-<sha256[:8]>-` (no `ENAMETOOLONG`,
  no owner collisions).
- Resume no longer reuses a `*_temp.wav` that is a symlink.
- Temp names keep the prefixes `cleanup_temp_files` already sweeps.

Affected sites: `modules/subtitles/srt_io.py`,
`modules/pipeline/translation.py`, `modules/media/ffmpeg_utils.py`,
`auto_subtitle.py`.

## 🔒 Security fix — `accelerate` PYSEC-2026-3804

`accelerate` ≤ 1.14.0 fails to sanitise sharded-checkpoint `weight_map`
entries (path traversal / named-pipe DoS). Bumped to `^1.15.0`.
