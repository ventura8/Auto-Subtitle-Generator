# v1.1.3 Release Notes

Release date: 2026-08-25

## Highlights

- Removed token-persistence side-effect from `_handle_hf_token_prompt`: the
  Hugging Face token entered at runtime is no longer silently written back to
  `config.yaml`, eliminating an unexpected file mutation and the associated
  security risk of persisting credentials on disk.
- Pinned FFmpeg download in `install_dependencies.ps1` to a specific build
  (`n9.0.1-6-g9d4ca21220`) with SHA256 integrity verification, replacing the
  rolling `master-latest` URL that could silently deliver a different binary.
- Added automated GitHub Release workflow (`.github/workflows/release.yml`)
  triggered on `v*` tags, with tag/`pyproject.toml` version cross-verification
  and authored release-description support (`docs/releases/v*_github_description.md`).
- Comprehensive agent-skills overhaul: all 11 skills under `.agents/skills/`
  fully rewritten to structured SKILL.md format with YAML frontmatter.
- Dependency updates: `transformers ^5.15.1`, `audio-separator ^0.44.5`,
  `pylint ^4.0.7`, `ruff ^0.16.4`, `mypy ^2.3.1`, `pyright ^1.1.411`,
  `types-pyyaml ^6.0.12.20260815`.

## Security & Correctness

- **Removed `_save_token_to_config`**: the function that atomically wrote the
  HF token back into `config.yaml` has been deleted from
  `modules/configuration/config.py` together with its dependencies
  (`_atomic_write_text_file`, `_escape_token_value`, `_upsert_hf_token_line`,
  and the `re`/`tempfile` imports). The token is now only set in
  `os.environ["HF_TOKEN"]` for the lifetime of the process.
- **FFmpeg pinned build + SHA256 gate**: `install_dependencies.ps1` now
  downloads a pinned FFmpeg release URL and validates the SHA256 checksum
  before extraction; a mismatch raises a hard error rather than silently
  using a potentially tampered archive.

## CI / Automation

- New `.github/workflows/release.yml`:
  - Triggers on `v*` tag push.
  - Runs `scripts/release-verify-tag-version.sh` to assert the tag equals the
    `pyproject.toml` version before creating the release.
  - Uses `docs/releases/v{VERSION}_github_description.md` as the release body
    when present; falls back to GitHub auto-generated notes.
  - Uses `softprops/action-gh-release@v2.3.2` with `contents: write`
    least-privilege scope.
- New `scripts/release-verify-tag-version.sh`: reads version via an inline
  Python `tomllib` script using a heredoc — no extra VERSION file required.

## Agent Skills

- All 11 modular skills rewritten under `.agents/skills/` with proper YAML
  frontmatter and structured instructions:
  `architecture-review`, `code-linter`, `docs-sync`, `fix-file`,
  `model-optimizer`, `pipeline-runner`, `pr-comment-resolution`,
  `release-prep`, `review-with-coderabbit`, `setup-dependencies`,
  `test-runner`.
- `release-prep` skill updated to document the `_github_description.md`
  naming convention and the end-to-end automated tagging flow.

## Tests

- Removed two tests (`test_save_token_to_config_replaces_existing_value`,
  `test_save_token_to_config_appends_when_missing`) that tested the now-deleted
  `_save_token_to_config` function.
- Added `test_handle_hf_token_prompt_empty_input_skips_env`: verifies that
  whitespace-only input does not set `HF_TOKEN` in the environment.
- Coverage gate remains ≥ 90% across all key modules.
