# Auto-Subtitle-Generator v1.2.0 — Cross-Platform Support + Real E2E Testing Matrix

## Release Summary

v1.2.0 introduces full cross-platform support for Linux and macOS, a
real-dependencies E2E test suite, a Docker-based validation harness, and
parity enforcement between the local quality gate and GHA CI. The release also
adds Windows GHA runner coverage to the E2E matrix, bringing the pipeline to
full tri-OS validation. Ubuntu executes all four E2E tests, while macOS and
Windows run the three-test subset excluding
`real_nllb_translator_cpu_execution`.

## What's New

### 🐧 Linux & macOS Native Support

- Added `launcher/main.go` — native Go source for lightweight standalone auto-installing
  launcher binaries (`start.exe` on Windows, `start` on Linux and macOS).
- Added `install_dependencies.sh` — cross-platform Bash installation script
  (Linux / macOS / WSL2) mirroring the existing `install_dependencies.ps1`.
- Added `run_local_pipeline.sh` — Bash equivalent of `run_local_pipeline.ps1`,
  executing exactly the same steps as GHA in order: suppression scanner, Markdown
  formatting, Python linting, type checking, security scans, Radon metrics, tests,
  coverage gate, badge generation.
- Added `start.sh` — Bash entry-point launcher with automated `.venv` installation.
- `modules/media/ffmpeg_utils.py`: platform-aware FFmpeg path discovery for Linux
  and macOS (system `ffmpeg` on PATH, no Windows-only assumptions).
- `modules/media/hardware_utils.py`: refactored `get_cpu_name` into OS-specific
  helpers (`_get_windows_cpu_name`, `_get_unix_cpu_name`) — Radon A-grade compliant.
- `modules/models.py`: decomposed `_detect_gpu_props` into smaller helpers to meet
  Radon cyclomatic complexity < 10.
- `auto_subtitle.py`: startup path resolution made OS-agnostic.

### 🐳 Docker Cross-Platform Test Harness

- `docker/Dockerfile.ubuntu` — Ubuntu 26.04 container with `uv`-managed Python 3.12.13,
  full dependency installation via `install_dependencies.sh`, E2E test execution.
- `docker/docker-compose.test.yml` — Compose harness covering:
  - `ubuntu-test`: `ubuntu:26.04` (Linux/CPU baseline)
  - `macos-test`: `auto-subtitle-macos-ssh-test` (a provisioned guest with
    Remote Login and an authorized SSH key)
  - `windows-test`: `dockurr/windows` (Windows via KVM)
- `docker/run_cross_platform_tests.sh` — Cross-platform container E2E runner:
  `./docker/run_cross_platform_tests.sh ubuntu`
- `.dockerignore` — excludes `.venv`, `__pycache__`, `.git`, and temporary
  files for lean builds.

### 🧪 Real-Dependencies E2E Test Suite

- `tests/e2e/test_real_pipeline.py` — 4 tests using zero mocks:
  1. `test_real_audio_extraction_and_duration` — real FFmpeg WAV extraction.
  1. `test_real_hardware_detection` — real GPU/CPU VRAM/core detection.
  1. `test_real_nllb_translator_cpu_execution` — real NLLB-200 distilled-600M
     translation in an isolated subprocess (avoids pytest conftest mock pollution).
  1. `test_real_cli_dry_run_or_help` — real CLI `--help` smoke test.
- Subprocess PYTHONPATH set explicitly so `modules.*` imports resolve on all platforms.

### 🔧 Import Safety

- The translation runtime does not install the optional `torchaudio` backend, so
  Transformers does not load an incompatible CUDA audio extension during text-only
  translation.

### ⚙️ CI/CD Parity & GHA Improvements

- `e2e_real_dependencies` GHA job now runs on all three OS runners:
  `ubuntu-latest`, `macos-latest`, `windows-latest`.
- Windows runner: `choco install ffmpeg`, `shell: pwsh` for pytest step.
- `POETRY_REQUESTS_TIMEOUT: 300` for large ML package downloads in CI.
- Local `run_local_pipeline.sh` runs the same checks as GHA.
