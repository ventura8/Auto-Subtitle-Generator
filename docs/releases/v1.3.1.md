# Auto-Subtitle-Generator v1.3.1 — Chunked Separation Symlink Hardening

## Release Summary

v1.3.1 closes a medium-severity local overwrite in chunked vocal separation.
Predictable scratch names under the per-video work directory
(`chunk_NNN.wav`, `stems.list`) were written with FFmpeg `-y` and
`open(..., "w")`, which follow planted symlinks. Both paths now land through
`safe_io` reservation / atomic text write and promote, matching the rest of
the pipeline. There are no CLI, config, or deliverable filename changes.

______________________________________________________________________

## Symlink-Safe Chunk Cuts and Concat Manifests

`write_audio_window` in `modules/media/ffmpeg_utils.py` reserves a private
scratch file beside the destination, points FFmpeg at that path, then
promotes onto the caller-requested name. A symlink at `chunk_NNN.wav` (or any
other target) raises `SymlinkRefusedError` and the victim file is left
untouched.

`concat_audio_files` writes `stems.list` through `atomic_text_writer` and
stream-copies into a reserved scratch file promoted onto the join target.
Planted links at either predictable name are refused the same way.

Call sites in `modules/pipeline/transcription.py` keep their predictable
scratch names for the separator and resume join; only the write path changed.

## Tests

- `tests/modules/media/test_ffmpeg_chunk_helpers.py` asserts FFmpeg never
  receives the predictable destination path, and that planted
  `chunk_000.wav` / `stems.list` / join-target symlinks leave dummy victims
  intact.

## Documentation

- `AGENTS.md` and `docs/pipeline_logic.md` document that predictable names
  inside listable work/scratch directories must not be opened with bare
  `open` or FFmpeg `-y`.
- Version bumped to 1.3.1 in `pyproject.toml` and the
  `modules/configuration/version.py` fallback.
